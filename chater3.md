# Northstar Support Deflection MVP
## Team Charter

### 1. Project Purpose

Our team will develop a Support Deflection MVP for Northstar Retail Co.

The system will help customers find immediate answers to common support questions without requiring a support agent.

The MVP will focus on:

- Order tracking
- Returns and refunds
- Product stock availability

---

---

### 3. Communication

The team will communicate through [WhatsApp/Discord/other].

Team members should:

- Respond to important project messages within 4 hours during working periods.
- Inform the team when they are blocked.
- Communicate delays before deadlines.
- Keep technical discussions focused on the project.

---

### 4. Meetings

The team will conduct short daily check-ins.

Each member will report:

**Yesterday:** What I completed.

**Today:** What I will work on.

**Blocked:** Any problem preventing progress.

At the end of each working day, members will update their assigned tasks.

---

### 5. Task Management

All project tasks will be recorded on the project board.

Every task should have:

- An owner
- Priority
- Definition of Done
- Status

Tasks should normally take no more than 4 hours.

Large tasks will be divided into smaller tasks.

---

### 6. Definition of Done

A task is considered complete when:

- The implementation is finished.
- The work has been tested.
- The relevant code has been committed.
- The project board has been updated.
- Required documentation has been updated.
- The work is ready for review or integration.

---

### 7. GitHub Workflow

The main branch will contain stable code.

Development work will be performed using feature branches.

Branch format:

`feature/<username>/<task-name>`

Example:

`feature/32sav/order-api`

Members should not directly push unfinished work to `main`.

Pull requests should be reviewed before important changes are merged.

---

### 8. Commit Convention

Commit messages will follow:

`<type>: <what changed> - <why it matters>`

Examples:

`feat: add order status endpoint - allows customers to track orders`

`fix: validate unknown order IDs - prevents invalid API responses`

`docs: add API documentation - helps frontend developers integrate endpoints`

---

### 9. Code Review

Team members will review important contributions before merging.

Reviews should consider:

- Functionality
- Code quality
- Bugs
- Naming
- Compatibility with the rest of the system

---

### 10. Conflict Resolution

If a disagreement occurs:

1. Discuss the issue respectfully.
2. Refer to the project requirements.
3. Test possible solutions where appropriate.
4. Seek assistance from the Project/Integration Lead if necessary.
5. Make a decision based on project requirements, quality and available time.

---

### 11. Accountability

Every team member is expected to make a visible contribution.

Evidence may include:

- GitHub commits
- Pull requests
- Code reviews
- Project-board updates
- Documentation
- Testing

Members who become blocked must communicate the issue rather than remain inactive.

---

### 12. Quality Standards

The team will prioritize:

1. Working functionality
2. Correctness
3. Usability
4. Clean and maintainable code
5. Documentation
6. Traceable individual contributions

---

### 13. Team Agreement

All team members have reviewed and agreed to follow this Team Charter throughout the Northstar Support Deflection MVP project.

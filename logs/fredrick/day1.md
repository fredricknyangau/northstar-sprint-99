## Day 1 Reflection 

### What happened
Led the Charter + Board workshop with the full team on a call. Reviewed each member's background and availability before accepting the team lead role, then proposed a role split based on stated strengths (Stephen/Fredrick - backend, Mark - database, Maria - frontend, Ibrahim - QA/docs).

Combined four separate charter drafts from teammates into one unified CHARTER.md, had each member sign off via their own feature branch and PR, then merged all five. Populated the project board with 14 tasks covering the full MVP scope (order status + returns), each scoped under 4 hours with an owner, priority, and Definition of Done.

Scaffolded the backend/frontend project structure, merged to main, and sent the team clear instructions on branch naming, commit format, and where each person's work lives in the repo.

### What went well
- Getting individual input from each teammate before assigning roles meant the split actually matched real skill levels instead of guessing.
- Having everyone sign the Charter via their own branch and PR gave real GitHub activity from all 5 people on Day 1, not just me.
- Task breakdown stayed disciplined - no task over 4 hours, each with a checkable Definition of Done.

### What was harder than expected
- GitHub Projects' issue-creation flow wasn't obvious at first (paste into description didn't work, had to use the built-in Assignee/Label buttons instead). Cost some time live on the call but got resolved by testing directly instead of guessing.
- Balancing team lead responsibilities (coordinating, drafting docs) with actually starting my own technical task meant Day 1 was mostly process work rather than code. Planning to start real backend work today.

### Self-assessment
Strong on collaborative discipline and process setup. Need to make sure I'm visibly contributing code, not just infrastructure, starting today - the evaluation weighs technical growth heavily and that trajectory needs to start showing soon.

# Day 1 Reflection

**What happened**

Participated in the Charter and Board workshop with the team, where we discussed the MVP requirements, assigned roles, and agreed on the development workflow. I took on the Frontend Developer role, focusing on the customer-facing interface using HTML, CSS, and JavaScript.

I reviewed the project structure and started building the frontend forms for the customer support experience. My initial implementation focused on allowing customers to submit questions, check order status, and initiate returns. I tested the interface locally and confirmed that the basic functionality was working.

**What went well**

* I was able to set up and work within my assigned frontend folder using HTML, CSS, and JavaScript.
* I successfully built and tested the initial forms and confirmed that the interface was functioning locally.
* I became more familiar with the team's Git workflow, including working on a feature branch, committing changes, pushing my branch, and creating a pull request.
* The team discussions helped me better understand how my frontend work needs to connect with the backend endpoints and database.

**What was harder than expected**

* The main challenge was understanding the exact scope of the frontend before implementation. I initially interpreted the "simple forms" more broadly and started building a general customer support interface.
* During the team discussion, I realized that we had not fully defined the user journey and how the order status and returns functionality would flow between the frontend, backend, and database.
* This meant I had to reconsider parts of my initial approach instead of continuing to build based on assumptions.

**Self-assessment**

Day 1 showed me that writing functional code is only one part of development. I need to improve my ability to understand the complete user journey and requirements before starting implementation. I also learned the importance of communicating with the backend and database developers early so that the frontend fields and API interactions remain aligned.

I feel that I made good progress with the frontend and gained practical experience working within a team codebase. Going forward, I want to be more deliberate about understanding the system design first, asking questions when requirements are unclear, and making sure my work remains aligned with the team's overall MVP.
